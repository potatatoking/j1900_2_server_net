# 网站按访问 IP 自动跳转

统一入口是 `https://example.net/`。只对首页 `/` 和 `/index.html` 的 GET/HEAD 请求跳转，页面路径和查询参数保留。浏览器中的页面片段（`#...`）由浏览器保留。

2026-10-16 已修复部分浏览器使用 HTTP 时出现的 SakuraFrp `503 #74`：日本 HTTPS 隧道 `10000002` 启用 `force_https = 301`，并已重启 OpenWrt `sakura-frp` 服务。所有 `http://example.net/...` 请求先由 FRP 节点升级到同路径、同查询参数的 HTTPS，再由网站执行本页的来源分流规则。配置与回滚见 [FRP 修复记录](../sakura-frp/README.md)。

| 来源 | 目标 |
| --- | --- |
| 校园网已知出口 `203.0.113.22`、`203.0.113.23` | `http://172.20.131.2:8080/` |
| 其他大陆 CN 地址 | `https://cn.example.net:40475/` |
| 其他地区或无法识别 | 保留 `https://example.net/` |

校园网优先于大陆规则。在大陆入口再次访问时，只对校园网来源跳转，其他来源原地访问。校园网地址本身不会跳转。重定向采用 302 和 `Cache-Control: private, no-store`，避免网络切换后被永久缓存到错误入口。

后台 `/admin`、API、静态资源和写入请求维持当前入口，后台登录不会被自动降级到校园网 HTTP。原有文章、上传图片和账号数据均沿用。

## 1. DNS 和 FRP 如何对应

阿里云 DNS 的默认线路：

| 主机记录 | 类型 | 记录值 | 用途 |
| --- | --- | --- | --- |
| `@` | CNAME | `edge-jp.example.net` | 日本 HTTPS 隧道，外部 443 |
| `cn` | CNAME | `edge-cn.example.net` | 江苏 TCP 隧道，外部 40475 |

DNS 不能按端口区分服务器，因此大陆入口单独使用 `cn` 子域名。无需更换域名 NS。

两条隧道仍在 OpenWrt 上运行，本地服务均为 `10.42.0.101:3000`。江苏隧道 ID `10000001` 保留外部端口 40475，通过自动 HTTPS 终止 TLS；日本隧道 ID `10000002` 保留原配置。

大陆证书文件位于 OpenWrt 的 `/etc/sakura-frp/cn.example.net.crt` 和 `.key`，权限 600。原主域名证书保留。证书通过 Debian 上已经安装的 acme.sh 手动 DNS 验证签发。

## 2. 网站上的配置文件

Debian 上实际生效的文件是：

```
/srv/web/app/server.js
/srv/web/app/visitor-routing.js
/srv/web/app/routing.json
/srv/web/app/china-cidrs.txt
```

本地 `routed-app/` 是本次修改所用的源码副本，不包含生产数据、管理员密码和私钥。

`routing.json` 中：

- `entryHosts`：允许自动跳转的访问域名及端口。
- `trustedProxyIps`：只有 `10.42.0.3` 这个 FRP 客户端允许提供访客 XFF 请求头。
- `campusCidrs`：校园公网出口，以及已确认的校园/本地内网网段。
- `campusTarget`：校园网直连地址。
- `mainlandTarget`：大陆 FRP 地址。
- `enabled`：总开关；设为 `false` 后保留原网站访问行为。

FRP 自动 HTTPS 的 HTTP 反代会在 `X-Forwarded-For` 尾部追加真实访客 IP；程序只采用可信代理提供的最后一个 IP，忽略访客自行填写的前半段。局域网直接请求不能通过随意设置 XFF 冒充大陆或海外来源。

配置在网站进程启动时读取。改完后运行：

```sh
sudo docker restart web
sudo docker inspect web --format '{{.State.Status}} {{.State.Health.Status}}'
```

## 3. 下次增加校园网出口

先让其他校内设备在关闭代理的情况下打开 `https://example.net/api/route`，查看 `clientIp`。确认它确实是校园网出口后，把它按 `/32` 格式添加到 `campusCidrs`，例如 `203.0.113.10/32` 仅为格式示例，不能直接加入。

没有学校提供的完整出口列表时，不能保证覆盖所有校园访客。目前按用户确认，先精确匹配已测出口：`203.0.113.22/32` 用于本次日本入口访问，`203.0.113.23/32` 用于本次国内入口访问；后者是在配置期间新增测得。校园 WAN `172.20.131.2` 来自 DHCP；若地址改变，要同时更新 `campusTarget` 和相关网络记录。

校园地址为既有映射 `172.20.131.2:8080 → 10.42.0.101:3000`。已经验证本地回环访问；不同校园 VLAN 之间是否允许直连，需要从直接连接校园网的设备验证。

## 4. 大陆地址表

地址表来自 APNIC 的 CN 分配记录，包含 IPv4 和 IPv6。本次快照为 2026-10-16，共 5497 个 IPv4 网段和 2018 个 IPv6 网段；判断在本地完成，没有每次访问调用第三方定位 API 的延迟。

这是地址分配国家识别，并非精准物理定位，个别跨境使用或 IP 转移可能判断不准。它不包含香港、澳门和台湾的独立地区代码。VPN/代理开启时，按代理出口识别，不能据此判断使用者实际是否在校园。

需要更新时，在本地工作区执行：

```powershell
python web-deploy/update-china-cidrs.py
scp -O web-deploy/routed-app/china-cidrs.txt deploy@10.42.0.2:/srv/web/app/china-cidrs.txt
```

然后在 Debian 执行 `sudo docker restart web`。更新脚本只用 Python 标准库，下载或校验失败不会覆盖原地址表；没有添加定时任务或新的依赖。

## 5. 自己检查是否生效

`https://example.net/api/route` 返回当前请求的 `clientIp`、`region` 和建议 `target`，不会触发跳转，也不会返回密码或其他请求头。`target: null` 表示当前入口不需要跳转。

需要临时留在日本入口时，访问 `https://example.net/?route=global`。该参数仅作用于带参数的这次访问，不设置永久偏好。

可以使用浏览器开发者工具 Network，查看首页的 302 和 `Location`；响应头 `X-Site-Route` 显示 `campus`、`mainland`、`other` 或 `unknown`。从统一入口进入仍然需要先连接日本节点，再收到跳转。

## 6. 证书续期

大陆证书在 Debian 的 `~/.acme.sh/cn.example.net_ecc/`，由 Let's Encrypt YE1 签发，到期时间为 2027-01-14 04:25:39 UTC（北京时间 12:25:39）。建议 2026 年 12 月中旬续期。沿用手动 DNS 验证；续期时重新发起申请，并按 acme.sh 当次输出更新阿里云 `_acme-challenge.cn` TXT，不要复用旧验证值。签发后把 `fullchain.cer` 和私钥分别复制到 OpenWrt 的 `.crt`、`.key` 文件，再重启 `/etc/init.d/sakura-frp restart`。

主域名的续期步骤见 `../sakura-frp/README.md`。两张证书需要分别续期；没有设置自动续期。

## 7. 验证与回滚

已启用上述规则并验证：Debian 从日本入口访问，按实测校园出口收到 302；浏览器从大陆入口访问，自动到达校园地址并显示正常首页。江苏节点的两个解析 IP 都通过可信 TLS 验证，最终首页 SHA-256 与修改前一致。通过 OpenWrt 向实际网站发送模拟的其他大陆来源请求，返回 302 和正确的大陆目标；海外代理来源保持原入口，伪造 XFF 前半段不能改变真实来源判断。网站健康检查正常，两条 FRP 隧道在线。

JavaScript 修改后执行了 `npm test`。Windows 中 31/32 通过，原有权限测试要求 Unix 文件模式 0600，而 Windows 返回 0666，因此该项在 Windows 失败。使用生产相同的 Linux Node.js 24.22.0 镜像执行该脚本对应的 `node --test`，32/32 全部通过，包括校园优先、IPv6、可信代理、伪造请求头、避免循环、静态资源和健康检查等验证。

Debian 备份目录为 `/srv/web/redirect-backup-20261016/`，包含原 `server.js`、Compose、私密 `.env` 及修改前的数据/上传文件备份。OpenWrt 备份目录为 `/etc/sakura-frp/backup-routing-20261016/`。

最快停用跳转的方法是将 `routing.json` 的 `enabled` 改为 `false`，再重启 web。恢复原服务器代码时可运行：

```sh
sudo cp /srv/web/redirect-backup-20261016/server.js /srv/web/app/server.js
sudo docker restart web
```

不需要恢复数据备份，跳转功能没有变更数据格式。大陆 DNS 和证书可继续保留作手动访问入口。
