# DNS 与 Clash Verge 修复记录

日期：2026-10-17，Asia/Shanghai。

## 已修复

1. **ISP 出口在规则模式中不可选。** 原全局增强脚本只新增 ISP 节点和 ISP 前置组，普通“手动切换”和“ChatGPT、Claude、Gemini、微软AI”组没有引用它。已修改全局 Script.js，动态向这两个组加入 ISP出口，并选中它。保留现有 SOCKS5 协议、认证信息与美国 01 前置节点；实测该协议可用。重载配置后，选项与选中状态均保留。
2. **代理端口冲突。** 另一个服务 com.vortex.helper 占用 7897，Verge 内核日志报告端口绑定失败，实际 mixed-port 为 0，而系统代理指向 7897。现在 Verge 独立使用 7896；verge.yaml、config.yaml、实际运行配置和 Windows 系统代理均为 127.0.0.1:7896。旧服务仍监听 7897，两个内核不再争用同一端口。
3. **DNS 异常。** 原主路由 .1 经校园 DNS 返回 cn.example.net 的 NXDOMAIN，以及错误的 Google A/AAAA 结果。已将主路由手动 DNS 设置为 10.42.0.3，备用留空；WAN 仍为 DHCP，地址仍是 172.20.131.2/17，网关仍是 172.20.128.2。
4. **局域网使用加密 DNS。** OpenWrt dnsmasq 已通过 127.0.0.1:7874 转交现有 Mihomo 加密 DNS。启用 OpenClash 的 DNS 转发管理（enable_redirect_dns=1），并重启验证，实际 dhcp.noresolv=1、server=127.0.0.1#7874。现有 DoH 上游经 ISP 出口访问 Cloudflare/Google。
5. **避免 DNS 环路。** OpenWrt LAN 接口的引导 DNS 改为 223.5.5.5、119.29.29.29，避免主路由 .1 指向 OpenWrt .3 后，OpenWrt 的备用解析又指回 .1。正常运行时客户端 DNS 仍经加密上游；这些普通 DNS 用于底层引导或恢复场景。
6. **Windows Verge DNS 持久化。** 全局 Merge.yaml 明确配置 AliDNS/DNSPod DoH、独立引导 DNS、代理服务器 DNS 和直连 DNS，并对 .lan 使用局域网解析，保留 fake-IP 模式及本地域名过滤。DNS AAAA 返回关闭；未更改订阅节点列表。Windows WLAN DNS 仍是 10.42.0.1，其上游已修复；本机 DNS 缓存已清除。

正常 DNS 链路：Windows/其他局域网设备 → 10.42.0.1 → 10.42.0.3 → Mihomo :7874 → 加密 DNS。容器直接使用 10.42.0.3。

Clash Verge 流量链路：应用 → 系统代理 127.0.0.1:7896 或 Verge TUN → ISP出口 → ISP前置（美国 01）→ 203.0.113.21 → 目标网站。Mihomo 根据 dialer-proxy 建立前置连接，最终公网出口为 203.0.113.21。
