# 双 J1900 个人服务器与博客平台

用两台二手 J1900 小主机，把 Debian 服务器、OpenWrt 旁路由、个人博客和命令行工具组合成一套可维护的个人服务平台。

模型推理由云端服务完成，小主机负责应用运行、网络转发与数据保存。项目包含源码、容器模板、配置示例和复现步骤；不包含可直接访问作者设备的账号、域名或代理凭据。

## 已实现的功能

- **独立服务部署**：博客与命令行工具分容器运行，各自保留工作目录和账号配置。
- **按容器分流**：指定服务使用 ISP 或普通代理，其余服务走本地宽带；主机和个人电脑单独配置。
- **个人博客**：图文发布、后台管理、站内搜索、留言、友链、活动统计和更新日志。
- **多入口访问**：支持局域网、校园网以及可选的 FRP / HTTPS 入口。
- **存储分离**：系统与容器运行层放在 SSD；机械盘用于工作文件、博客内容、缓存、日志归档、备份与个人云盘。
- **验证与维护**：提供网络参数校验、应用测试和更新时的数据保留说明。

IP、时区和语言设置只是环境配置，不保证任何第三方账号的可用性。AI 服务所需账号、订阅或 API 凭据需自行准备。

## 设备分工

| 设备 | 配置 | 职责 |
| --- | --- | --- |
| Debian 主机 | J1900、8GB DDR3、64GB mSATA SSD | Docker、博客与命令行工具 |
| OpenWrt 主机 | J1900、2GB DDR3、32GB mSATA SSD、500GB SATA 硬盘 | 指定容器分流、磁盘共享与网络服务 |
| 主路由 | 双频无线路由器 | 上级网络接入、DHCP 和必要的端口映射 |
| 交换机 | 可选千兆交换机 | 网口不足时扩展连接 |

两台主机都只有一个千兆网口，因此 OpenWrt 使用旁路由方案。无线协商速率、网口速率、宽带套餐和代理速度是不同指标，不能互相替代。

## 部署结构

~~~text
个人电脑 / 校园网终端
          |
        主路由
          |
      局域网交换网络
       /           Debian 主机     OpenWrt 旁路由
   |                |
   |          指定容器的代理出口
   |
   +-- 博客、CLI 工具、云盘程序
   +-- SSD：系统、镜像、运行元数据
   +-- NFS：机械盘上的持久文件与云盘空间
~~~

网络访问和存储共享是两条独立链路。容器把默认网关设为 OpenWrt，不等于它必然走代理；还要检查 OpenClash 白名单、容器内部重定向和宿主机的出口规则。

## 快速体验博客

需要 Node.js 22+。博客使用 Node 内置模块，不需要先安装 npm 依赖。

~~~sh
cp 03_blog/source/.env.example 03_blog/source/.env
# 编辑 .env，设置自己的 BLOG_ADMIN_PASSWORD
npm run start:blog
~~~

打开 http://localhost:3000，管理员入口为 /admin。首次启动后请完成登录验证；直接打开 HTML 文件只能查看静态演示。

~~~sh
npm test
python -m unittest discover -s automation -p 'test_*.py'
~~~

完整的安装顺序、容器地址规划、存储和网络验收见[从零配置指南](docs/FROM_ZERO.md)。Docker 部署见[博客模板](03_blog/deployment/README.md)。

## 为什么做这个项目

起初，我只是想搭建一台可以长期开机的小服务器，方便远程使用命令行工具。两块二手 J1900 主板、mSATA 固态硬盘和笔记本内存，让这件事有了一个成本较低的起点。

真正花时间的并不是把服务启动起来，而是解决网卡未启用、DNS 异常、地址冲突、校园网回程路由和更新覆盖数据这些问题。博客、远程访问和云盘也是在这个过程中逐步补齐的。

这次实践让我开始习惯先画清数据流和网络流，再分层排查；修改前留备份，修改后检查实际行为，而不只看配置文件里的开关。后续希望把单片机采集的数据接入这套平台，继续完善监控、备份和恢复流程。

总而言之，尽管整个项目99%都是许愿式编程的结果，但这也是我第一个动手实践的小项目，而且结果也挺不错的，希望能在这条路上越走越远。
