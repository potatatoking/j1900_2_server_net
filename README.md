# 基于 J1900 的个人服务器与博客平台

两台 J1900 主机分别运行 Debian 和 OpenWrt，提供个人博客、命令行工具容器、指定容器代理以及校园与公网访问。正式维护分支为 main。

## 项目入口

| 部分 | 负责什么 | 入口 |
| --- | --- | --- |
| 服务器与网络 | 主机、Docker、CLI 工具、路由、代理、FRP 和 DDNS | [说明](01_server_net/README.md) |
| 个人博客 | 内容、图片、留言、活动统计与入口分流 | [说明](03_blog/README.md) |

博客正式源码位于 03_blog/source，部署模板位于 03_blog/deployment；automation 只负责本地参数校验与材料生成。博客的源码与原有提交历史继续保留。

## 运行与测试

使用 Node.js 22+，无需安装额外 npm 依赖。先将博客源码目录的 .env.example 复制为 .env，并设置管理员密码。

```sh
npm run start:blog
npm test
python -m unittest discover -s automation -p 'test_*.py'
```

博客默认入口为 http://localhost:3000，管理员入口为 /admin。根目录测试包含服务器密钥路由和博客；启动或测试命令不会连接路由器或部署生产服务。Windows 的 Unix 文件权限断言差异需要单独记录，不能删除断言。

修改 JavaScript 后必须运行 npm test，安装依赖优先使用 pnpm，添加新依赖前先确认。真实凭据、运行配置、账号数据、文章和上传文件不提交 Git。博客更新保留 .env、routing.json、data 与上传目录。

## 部署计划

复制 automation/parameters.example.json 为私有参数文件，按实际网络填写。

```sh
python automation/prepare_plan.py parameters.local.json --check
python automation/prepare_plan.py parameters.local.json --out generated
```

生成器只写本地材料。服务器与网络规则由第一部分管理，博客的业务数据与应用代码独立保存。更多内容见 [项目结构](PROJECT_STRUCTURE.md) 和 [功能更新](CHANGELOG.md)。

## 项目介绍

项目名称：基于 J1900 的个人服务器与博客平台

一、项目目标

利用两台 J1900 小主机搭建低成本个人服务平台，实现个人博客发布、云端 AI 服务统一接入、指定容器网络分流，以及局域网、校园网和公网访问。

二、技术栈

硬件与系统：两台 J1900 小主机，分别运行 Debian 和 OpenWrt。

容器部署：使用 Docker 和 Docker Compose 管理服务，通过 macvlan 为容器分配独立 IP。

网络配置：使用 OpenClash 和 Mihomo 实现指定容器分流，通过前置代理连接 ISP 出口。

博客开发：采用 HTML、CSS、JavaScript 和 Node.js，使用 JSON 文件保存内容，独立保存上传图片。



远程访问：使用 SSH、端口映射、SakuraFrp、域名解析和 HTTPS，并结合 Python 与阿里云 DNS API 实现校园入口 DDNS。

版本管理与验证：使用 Git 管理代码，通过自动化测试、文件校验和实际访问检查验证部署结果。

三、操作流程

第一步，准备硬件与系统。完成供电和网络连接，部署 Debian 与 OpenWrt，将 OpenWrt 从启动 U 盘迁移到 SSD，并确认能够独立启动。

第二步，配置基础网络。确定主路由、服务器和旁路由的 IP，配置 SSH、网关、DNS 和 DHCP 地址范围。

第三步，部署容器。安装 Docker 和 Compose，将博客和 AI 命令行工具分别部署，配置独立 IP、数据挂载及重启策略。

第四步，配置网络分流。通过 OpenWrt 接管指定 AI 容器的流量，配置前置代理与 ISP 出口，检查实际出口和域名解析。

第五步，开发个人博客。实现内容展示、后台登录、图片上传、留言回复和搜索功能，并将运行数据与代码分开保存。

统一不同 AI 服务的调用入口，逐步加入流式响应、历史记录、文件操作、对话分支和命令审批。

第七步，配置远程访问。校园网内通过端口映射访问服务，公网通过 FRP 和 HTTPS 访问博客，使用 DDNS 自动更新校园入口地址。

第八步，测试与整理。验证网络连通性、服务鉴权、容器重启和数据持久化，整理源码、教程和配置材料。

四、主要困难与解决办法

1. 系统迁移困难

启动 U 盘容量大于目标 SSD，无法直接整盘复制。通过重新规划分区、文件级复制、修正启动配置和校验文件，完成迁移。

2. IP 地址冲突

容器固定 IP 曾与其他设备冲突，主路由静态绑定数量也有限。通过缩小 DHCP 动态地址池，将容器固定地址放在动态池外，减少冲突。

3. 校园网与 Docker 网段重叠

校园网地址范围与 Docker 默认网段重叠，导致回程流量异常。通过添加更具体的校园网路由，使流量经主路由返回。

4. 代理连接与 DNS 异常

ISP 服务拒绝直接连接，DNS 也曾出现异常解析。通过前置代理连接 ISP，并重新梳理 DNS 转发链路、设置独立引导 DNS，恢复访问。

5. 校园入口地址变化

校园 WAN 使用动态地址，变化后原 IP 无法继续访问。通过定时读取主路由 WAN 地址并更新阿里云 DNS，使访问入口保持为固定域名。

6. 博客功能与数据维护问题

中文和表情跨网络分块时可能解码异常，快速切换页面时可能出现旧动画回写。分别通过完整接收 Buffer 后解码、增加动画版本标记和取消机制解决；同时独立保存数据与图片，避免更新代码覆盖内容。

7. AI 服务接口不统一

不同 AI 工具的调用方式和输出格式存在差异。通过 Node.js 网关与 Python 桥接程序统一处理请求、流式输出和任务状态。
