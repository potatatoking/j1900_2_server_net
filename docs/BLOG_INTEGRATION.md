# 博客整合与版本交接

[返回项目首页](../README.md)

正式博客源码统一位于 03_blog/source。部署模板、参考工具与教学示例分别保存在相邻目录，不作为第二套生产源码维护。

## 核对结果

旧博客仓库有 main、officaluse1.0、officaluse1.1 三个分支：

| 原分支 | 在总项目中的对应内容 |
| --- | --- |
| main | 早期博客实现；功能已由当前正式源码覆盖 |
| officaluse1.0 | 页面交互、字体和 UTF-8 修复；后续版本已经包含 |
| officaluse1.1 | 正式博客基础，已整合到 03_blog/source |
| main 独有的 PRIVACY.md | 隐私边界已整理到总项目根目录的 PRIVACY.md |

总项目在导入博客后继续增加了工作页更新日志和测试，因此当前源码并不与旧分支逐字相同。核对重点是正式源码、独有文档、功能覆盖和开发历史，而不是只看提交 ID 是否相同。

原三个分支的完整 Git 历史已生成删除前的私有 bundle 备份，放在仓库之外。总项目保留经整理的博客开发历史；不会为复原旧提交 ID 把旧分支重新推入维护分支。

原仓库没有需要单独迁移的 Issue、PR、Release 或 Wiki。后续源码、文档和功能更新统一在本仓库 main 分支维护。

## 部署边界

仓库中的默认域名和账号是示例。文档整理不覆盖线上博客的文章、图片、账号、活动同步凭据或访客分流配置。

需要更新服务器程序时，另行备份并验证自己的 .env、routing.json、data/ 和上传目录。删除旧代码仓库不会删除服务器上的运行容器及其数据。
