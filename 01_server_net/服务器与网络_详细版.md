# J1900 服务器与网络从零搭建教程
详细版  按操作顺序学习与复现  2026年10月17日

本教程搭建一套由主路由、Debian Docker 服务器和 OpenWrt 旁路由组成的网络。你只需掌握 C 的基础语法即可开始，正文说明用途，附录提供可复制的配置与源码节选。

## 一 先看清设备与连接

项目记录中的 Debian 和 OpenWrt 都使用 J1900 平台。Debian 检测为四核、约 7.6 GiB 可用总内存、约 55 GiB 根分区；OpenWrt 从 128 GB U 盘迁到 32 GB SSD，使用 Legacy BIOS。主路由为中兴 E8822。这里的容量是记录中的设备信息，不是采购最低要求；待机内存低也不能代表能同时高速编译多个项目。

接线顺序是校园网络接主路由 WAN，Debian 和 OpenWrt 的 LAN 接主路由 LAN 或同一交换机。OpenWrt 作为同网段旁路由使用；不要把 Debian 接到另一层未知网段后直接照抄 IP。先用网线、显示器和键盘完成系统与网络恢复，再依赖 SSH。

|角色|项目地址|主要工作|
|---|---|---|
|主路由|10.42.0.1/24|校园 WAN 上网 DHCP 与端口转发|
|OpenWrt|10.42.0.3/24|OpenClash DNS FRP|
|Windows|10.42.0.4/24|开发与浏览器管理|
|博客 web|10.42.0.101:3000|个人博客及独立后台|
|codex|10.42.0.103|CLI Chat 与 Work|
|antigravity|10.42.0.104|Google CLI 及 Chat|
|deepseek-harness|10.42.0.105:3080|Harness 与 Work|
|zcode|10.42.0.106:3030|智谱工具网页|

IP 是设备地址，端口是该设备上服务的入口。10.42.0.103 不需要单独开放 SSH：先 SSH 到 Debian，再 docker exec 进入容器。网关决定去外网的下一跳；DNS 把域名查成地址；二者都正确才容易正常上网。

最终地址池已调整为 .2 至 .100，七个容器 .101 至 .107 在动态池外。主路由静态绑定容量只有十条，因此保留原有设备绑定，容器通过 Compose 自己固定 IP。早期记录中的“尚需排除容器 IP”已由缩小地址池处理。

## 二 准备系统与 SSH

以下为新机器复现路线。原会话开始时系统已能使用，完整 Debian 安装向导属于补充教学。下载 Debian 官方 amd64 安装镜像，核对官网 SHA256，制作启动 U 盘，按启动菜单进入安装器。给 Debian 选择正确系统盘，设置普通用户、主机名和强密码，软件选择中勾选 SSH server 与标准系统工具；是否安装桌面由需要决定。写盘前确认型号和容量，尤其不能误选已有数据盘。

安装后在 Debian 本地终端输入 hostnamectl、ip -br addr、ip route。先记录实际网卡名；本项目为 enp3s0。如果没找到 SSH 服务，先取得安装基础软件的授权，再执行附录中的安装命令。看到 ssh 服务 active、22 端口监听后，才能从 Windows 连接。

Windows 打开 PowerShell。输入 ssh deploy@10.42.0.2；OpenWrt 输入 ssh root@10.42.0.3。第一次连接会询问主机指纹，应与设备本地显示的指纹核对。输入密码时终端不显示字符是正常现象。登录后提示符改变，后面的 Linux 命令才是在服务器上运行。

建议配置密钥：在 Windows 用 ssh-keygen 生成带口令的 ed25519 私钥，把 .pub 公钥追加到 Debian 用户的 ~/.ssh/authorized_keys。私钥留在自己电脑；公钥可以交给服务器。另开一个终端验证密钥登录成功后，再考虑关闭密码登录，避免把自己锁在门外。OpenWrt Dropbear 的公钥位置通常为 /etc/dropbear/authorized_keys，与 Debian 不同。

已有 SSH 后，AI 可以自动检查系统、传文件和部署。但浏览器 OAuth、MFA、DNS 手动 TXT 和物理拔 U 盘仍可能需要本人完成，提示词不能代替这些外部操作。

## 三 固定 Debian 与主路由的网络

先保持 Debian 默认网关为 .1，暂不让宿主机整体进入代理。检查系统由 ifupdown、NetworkManager 还是 systemd-networkd 管理网络，只修改实际生效的那一套。本项目的校园持久路由使用 if-up.d，说明要特别核对 ifupdown。附录提供该方式的配置例子；若机器用 NetworkManager，就由 AI 按实际连接名称生成 nmcli 配置。

在主路由后台记录原 DHCP、设备绑定和 WAN 信息，缩小动态范围至 .2–.100，保留 Debian .2、OpenWrt .3 和个人电脑的既有绑定。不要一次性清空旧绑定。对 .101–.107 逐个检查在线冲突，同时核对自己的静态地址台账；ARP 检查只能发现当前在线设备。

修改网络前备份文件，保留本地屏幕或备用 SSH。先修改配置，验证路由与 DNS，再安排网络重载。重载会短暂断开 SSH；看到连接中断不等于系统损坏。恢复后检查 ip route、getent hosts 和 HTTPS 请求。

## 四 OpenWrt 系统与 SSD 迁移

本项目 OpenWrt 记录为 25.12.5 x86/64、ext4 根分区，采用 APK 包管理。先执行 cat /etc/openwrt_release、uname -m、command -v apk 和 lsblk 或 cat /proc/partitions。不要把 Debian 的 apt 命令用于 OpenWrt，也不要在 APK 系统上照抄旧 opkg 安装教程。

迁移的关键困难是源 U 盘比 SSD 大。原操作没有把整个 128 GB 盘直接 dd 到 32 GB 盘，而是制作只读文件树快照，在 SSD 建立适合容量的 MBR 分区和 ext4 文件系统，保留启动所需区域，复制文件、权限与扩展属性，再修正 GRUB 的根 PARTUUID。

实际源盘是 /dev/sdb，目标是 /dev/sda，但这些名字在另一台机器上可能相反。实际结果为 SSD 根 PARTUUID 73536432-02，根分区约 28.9 GiB。933 个系统普通文件哈希一致，文件系统检查与 chroot 检查通过。用户关机、拔出 U 盘、重启后，记录确认系统仅从 SSD 启动。

新手首次部署可以直接把匹配 Legacy BIOS 的官方 x86 镜像写入确认后的目标盘；如要保留现有插件配置，则采用迁移方式。磁盘写入与重分区必须在当次重新核对目标盘后执行，不能把历史 /dev/sda 当成授权对象。附录保留可安全检查的命令与实际迁移记录，完整写盘步骤由总 Prompt 根据盘型和备份生成。

## 五 设置 OpenWrt 旁路由

在 LuCI 的网络接口中，将 LAN 设为静态 .3/24、网关 .1；LAN DHCP 关闭，由主路由统一分配地址。旁路由不再广播第二套地址池，能避免手机或容器意外得到错误网关。IPv6 RA 与 DHCPv6 在本项目中也关闭；未来启用 IPv6 要同时设计 IPv6 代理与防泄漏，不能只验证 IPv4。

原排障发现 network.lan.giveaway 拼写错误，应为 network.lan.gateway。UCI 是 OpenWrt 配置命令：uci set 只改变待提交值，uci commit 保存到配置文件，服务 reload 才让运行配置重新读取。修改后检查 ip route 中是否存在 default via 10.42.0.1 dev br-lan。

最终 DNS 又做过修复：主路由 .1 指向 .3；OpenWrt dnsmasq 转发到 Mihomo 的 127.0.0.1:7874；Mihomo 用加密 DNS。OpenWrt 的引导 DNS 为 223.5.5.5 和 119.29.29.29，避免 .1 指向 .3、.3 又指回 .1 的环路。引导 DNS 用来先解析代理服务器和恢复连接，不等同于日常所有请求都明文解析。

## 六 安装 Docker 与 Compose

Docker 镜像相当于打包好的程序环境；容器是镜像运行后的实例；挂载卷把重要数据放在容器外。删除或重建容器时，只要卷和路径保留，账号与文章就能继续使用。Compose 用 YAML 统一描述镜像、IP、环境变量、数据目录和重启策略，减少手工 docker run 的差异。

先检查 docker version 和 docker compose version。已有 Docker 则复用。新机按 Docker 官方 Debian 安装页配置签名源并安装 Engine 与 Compose 插件，具体命令见附录。安装软件前向用户确认清单，包安装优先采用系统适合的管理器；JavaScript 项目增加依赖优先 pnpm。

不要随意把用户加入 docker 组来绕开 sudo：能控制 Docker 通常也能取得宿主机高权限。日常教程使用 sudo docker，权限范围更容易看清。

## 七 创建固定 IP 的 macvlan 网络

macvlan 让容器在主路由看来像独立设备。使用父网卡 enp3s0，网段 .0/24，网关 .3，每个容器 DNS 也为 .3。这样可按容器源 IP 区分代理策略，博客和 AI 工具各有独立地址。

先 docker network inspect proxy_lan；不存在再创建，存在则比较驱动、父网卡、网段和网关，不要删除正在使用的网络。所有 Compose 用 external: true 引用同一网络，并给服务设置 ipv4_address。这个模式不依赖宿主机 ports 发布端口，浏览器直接访问容器 IP。

一个常见困难是 Debian 无法直接访问同宿主机的 macvlan 容器，这是 Linux 的隔离行为。其他 LAN 设备能访问而 Debian 自己不能，并不说明网站没启动。不要为了这个问题开放整个 Docker socket 给网页。

## 八 部署 AI 工具容器

独立部署博客 .101。先确认每个地址无冲突，再使用对应目录的 Dockerfile、Compose 和 deploy.sh。部分镜像构建复用已有 local/web 或 DeepSeek 镜像，不能跳过它们的前置依赖。

源码包 01_server_net/source 保存原部署文件。Codex 从官方 npm 发布包提取 CLI 并验证 SHA512；Antigravity 根据官方 manifest 验证安装包；Harness 使用官方 npm 包；ZCode 固定官方仓库提交并按锁文件构建。版本是本次记录，不是永远最新的版本；换版本须重新核对官方说明和校验值。

工作区通常挂载到 /workspace，账号数据挂载到各 CLI 的用户配置目录。先 docker compose config 检查合并后的配置，再构建并 up -d --wait，最后检查版本、健康状态与重启持久化。config 输出可能包含环境值，只在自己的终端查看，不上传原样日志。

登录成功只能证明认证有效，不代表已完成付费模型推理。

## 九 OpenClash 与 ISP 链式代理

项目先安装 PassWall2，随后按用户要求改为 OpenClash。最终方案只使用 OpenClash 0.48.002 与 Mihomo v1.19.32 amd64-v1；旧 PassWall2 专用包和配置在备份后移除。amd64-v1 面向较老 CPU，适合这里的 J1900；不能把新 CPU 指令集构建直接用于旧平台。

新环境先检查固件版本、架构、包源、内核匹配和剩余空间，再根据 OpenClash 官方安装说明准备依赖与 APK。导入自己的订阅，确认至少一个节点可以连接，先测试普通出口，再增加 ISP。订阅 URL 含访问凭据，存入路由器私有文件即可，不能写进 Git。

实际链路为容器 → OpenWrt TUN → 美国自动备用组 → ISP HTTP CONNECT → 目标。ISP 地址和端口不代表自带 TLS；项目中的 type: http 未因端口 443 就自动变成 HTTPS。ISP 拒绝中国大陆来源直连，因此 dialer-proxy 指向美国备用组，让连接 ISP 的请求先经美国节点。

备用组按照美国 01、02、03、04、05 顺序选可用线路，每 60 秒探测，超时 5 秒。切换的是前置中转，最终出口仍是同一个 ISP。原覆写脚本通过名称规则匹配五个节点，找不到或重名就中止，因此新订阅应先检查节点名并按实际修改映射。

仅 .102、.103、.104 的源 IP 规则指向 ISP出口，并在 OpenClash 访问控制中加入透明代理白名单。规则列表有源 IP 条目但防火墙白名单没接管流量时，策略也可能不起作用。局域网访问应保留直连。HTTP CONNECT 这条链路不承载普通 UDP，所以最终方案不能表述为所有 TCP 与 UDP 都能代理；DNS 使用 DoH 走 TCP。

先在路由器私有文件配置 ISP，再安装覆写脚本，执行 sh -n、Mihomo -t、fw4 check，通过后重启 OpenClash。覆写方式在订阅刷新或服务重启时重新生成规则，比只手改生成后的 YAML 更持久。具体读码见附录。

## 十 从容器内部验证出口

在 Debian 执行 docker exec codex curl --noproxy '*' https://1.1.1.1/cdn-cgi/trace，检查 ip 和 loc。--noproxy '*' 排除 HTTP_PROXY 等环境变量影响，确认透明代理实际效果。三个受控容器应看到所配置的 ISP 出口；未选择的 .105 等不能因规则写错而一起被代理。

再请求 Google generate_204、普通 HTTPS 网站和 DNS 查询。只有 IP 查询成功还不足以证明模型 API 能用；最后从对应 CLI 查询模型或账号状态，必要时经用户授权进行小额推理测试。记录时间、容器、出口、HTTP 状态与失败原因，不能把模拟测试写成真实网络结果。

项目记录已验证三台容器最终出口为 203.0.113.21、地区 US、Google 返回 204，并在 OpenClash 重启后复查。Windows Clash Verge 是另外一条配置：它后来把端口从冲突的 7897 改为 7896；容器透明代理不依赖电脑保持开机。

## 十一 处理校园网与 Docker 网段重叠

校园 WAN 属于 172.20.128.0/17，而 Docker 默认 bridge 为 172.20.0.0/16。Debian 可能把去校园的回复错误地送往 docker0。项目增加更具体的 /17 路由，经 .1 从 enp3s0 返回校园网络；最长前缀匹配会让 /17 优先于 /16。

先 ip route get 校园测试地址，确认命中哪条路由；临时用 ip route replace 验证，再将原 campus-route 脚本放入 /etc/network/if-up.d，权限 755。若使用 NetworkManager，要改为它的持久路由配置。不要只重启后发现失效才补文档。

## 十二 主路由端口转发与访问

在 E8822 后台找到 NAT 或端口转发，选择实际 WAN DHCP 连接，以 TCP 创建下表规则。目标地址填写 LAN 设备或容器，目标端口填写真实监听端口。主路由自身的 SSH 与容器访问不是同一条映射。

|规则|校园外部端口|内部目标|
|---|---|---|
|Debian SSH|2202|10.42.0.2:22|
|OpenWrt SSH|2203|10.42.0.3:22|
|OpenWrt HTTPS|8443|10.42.0.3:443|
|博客|8080|10.42.0.101:3000|

最新会话确认校园 WAN 已从 172.20.131.2 改成 172.20.132.189。校园网可用入口为新地址加外部端口；这是校园私网地址，不能假定手机流量或任意公网都能访问。

SSH -L 的 127.0.0.1 只绑定运行命令的电脑，电脑建立隧道不等于手机也能使用该 localhost。

博客自动分流快照里的 campusTarget 仍是旧 .131.2。WAN 变化后，要先核对服务端 routing.json，必要时改成当前 .132.189:8080 并重启 web；本次文档整理没有替服务器修改这个文件。新部署参数统一填写当次真实 WAN，不把历史快照当成永久值。

## 十三 FRP 域名与证书

FRP 客户端在 OpenWrt 主动连接公网节点，再把外部访问转回 .101:3000，适合没有独立公网入站地址的网络。主路由校园转发只解决校内访问，FRP 解决公网入口，两者可以并存。

先在 SakuraFrp 后台创建隧道，确认账号可用节点支持建站。项目的日本 HTTPS 隧道提供主域名 443，大陆 TCP 隧道提供 cn 子域名的 40475。两条本地目标都应为 .101:3000，不能因外部 HTTPS 就把内部端口填成 443。

客户端安装、procd 自启动脚本见源码 sakura-frp。服务的工作目录是 /etc/sakura-frp，启动参数私有文件权限 600；域名对应的 .crt 与 .key 也放这里。先启隧道、验证本地 HTTP 和在线状态，再配置 DNS CNAME 指向节点域名。CNAME 不包含 :端口，端口要写在访问 URL 中。

项目使用 acme.sh 与 Let's Encrypt DNS-01。工具给出 TXT 名称和值，在阿里云添加当次 _acme-challenge，等待公共 DNS 查到，完成签发；将完整证书链和匹配私钥传到 OpenWrt。手动 DNS 模式每次续期仍需更新 TXT，没有自动续期任务。未来要全自动，需本人提供最小权限 DNS API 授权并配置部署钩子。

HTTP 入口曾出现 SakuraFrp 503 #74，原因是只启用 HTTPS 隧道。后台设置 force_https=301 后，HTTP 请求正确升级为 HTTPS。自有域名的可信证书与服务商节点域名不是同一主机名，不能把 curl -k 能打开当作 TLS 验证通过。

## 十四 常见故障与定位顺序

SSH 连接超时：先确认 IP 与 WAN 是否变化，再检查设备在线、22 监听、校园转发和回程路由。Permission denied 是认证失败，和网线、DNS 超时是不同问题。不要反复重装 Docker 来处理 SSH 密码问题。

网站在其他电脑能开、Debian 不能开：检查 macvlan 隔离，改用内部 bridge 或容器内健康检查。网站容器里没有 bash：使用 docker logs、inspect 或执行 node，不要默认精简镜像有 /bin/sh。

模型列表慢：检测耗时包含 CLI 启动、账号和目录读取，不是纯网络延迟。连接检测成功但推理超时：检查 SSE 心跳、上游超时与 CLI 原生审批。网站发消息和后台任务需要不同能力配置，不能因为 Chat 能用就默认 Work 能用。

域名 NXDOMAIN：分别查 .1、.3 与公共 DNS，区分 CNAME 正常但最终 A 记录缺失、缓存、上游错误和 DNS 环路。代理出口不对：核对源 IP、白名单、规则顺序、dialer-proxy 和应用自己的代理变量。不要公开控制面板或把订阅配置复制进问题反馈。

## 附录一 常用命令及执行位置

Windows PowerShell 连接设备，尖括号表示要替换，不是命令组成部分。

Debian 本地终端或已登录的 SSH 中检查系统。apt update 只更新软件索引，apt install 才安装包；需要安装前先确认依赖清单。

## 附录三 ISP 配置与覆写源码

在路由器 /etc/openclash/custom/isp-private.yaml 保存下列模板并替换凭据，chmod 600。这里 203.0.113.10 为文档示例地址，不能直接当作真实 ISP。脚本会补 dialer-proxy；如实际供应商提供 SOCKS5，先验证后改 type，不能仅凭端口猜协议。
```yaml
name: ISP固定出口
type: http
server: 203.0.113.10
port: 443
username: REPLACE_LOCALLY
password: REPLACE_LOCALLY
```

下面是原覆写脚本的生效部分。它读入生成的订阅 YAML，找到五个美国节点，重建同名组，加载私有 ISP，再把三个源 IP 规则放到优先位置。原文件前面还有 OpenClash 提供的接口示例；复用时使用源码完整文件。
```
# BEGIN US AUTOMATIC FAILOVER AND ISP EXIT
# Keep priority US01 -> US05; probe IP HTTPS so proxy DNS cannot block health checks.
ruby -ryaml -e '
path = ARGV.fetch(0)
c = YAML.load_file(path)
group = "美国自动备用"
nodes = (1..5).map do |i|
  candidates = c.fetch("proxies").select { |p| p["name"].include?("美国") && p["name"].match?(/\b0?#{i}\b/) }
  abort "US node #{i} missing or ambiguous" unless candidates.size == 1
  candidates.first.fetch("name")
end
c["proxy-groups"] ||= []
c["proxy-groups"].reject! { |g| g["name"] == group }
c["proxy-groups"].unshift({
  "name" => group, "type" => "fallback", "proxies" => nodes,
  "url" => "https://1.1.1.1/cdn-cgi/trace", "interval" => 60,
  "timeout" => 5000, "lazy" => false, "expected-status" => "200-399"
})
# The provider rejects mainland China source IPs. Dial the ISP through US failover.
# Credentials live only on the router in a root-readable file.
isp = YAML.load_file("/etc/openclash/custom/isp-private.yaml")
isp_name = isp.fetch("name")
isp["dialer-proxy"] = group
c["proxies"].reject! { |p| p["name"] == isp_name }
c["proxies"] << isp
isp_group = "ISP出口"
c["proxy-groups"].reject! { |g| g["name"] == isp_group }
c["proxy-groups"].unshift({"name" => isp_group, "type" => "select", "proxies" => [isp_name]})
rules = [102,103,104].map { |ip| "SRC-IP-CIDR,10.42.0.#{ip}/32,#{isp_group}" }
c["rules"] = rules + c.fetch("rules", []).reject { |r| r.match?(/^SRC-IP-CIDR,192\.168\.5\.10[234]\/32,/) }
c["dns"] ||= {}
c["dns"]["proxy-server-nameserver"] = ["223.5.5.5", "119.29.29.29"]
c["dns"]["nameserver"] = ["https://1.1.1.1/dns-query#" + isp_group, "https://8.8.8.8/dns-query#" + isp_group]
c["dns"].delete("fallback")
File.write(path, c.to_yaml)
File.chmod(0600, path)
' "$CONFIG_FILE"
# END US AUTOMATIC FAILOVER AND ISP EXIT

exit 0
```
